# 屏译交互修复与 Chrome/Edge 译文跟随设计

## 背景

当前版本已完成屏幕框选、Windows OCR、DeepSeek 翻译、原位覆盖和侧边显示，但实际使用中发现四个问题：

1. 全局快捷键固定为 `Alt + Shift + T`，设置页不能真正修改，并且该组合键会与浏览器操作冲突。
2. 侧边翻译窗口拖动不可靠；译文较长时内容会把底部功能按钮挤出屏幕。
3. 主设置窗口和侧边翻译窗口的滚动条只能拖动，鼠标滚轮不能滚动内容。
4. 原位译文使用固定屏幕坐标，Chrome/Edge 网页滚动后会与原文错位。

本设计把前三项作为基础交互修复，然后为普通 Chrome/Edge 网页增加低延迟滚动跟随。其他桌面程序继续使用现有静态翻译，不引入持续截图和持续 OCR。

## 目标

- 用户可以录制、验证、保存和恢复全局快捷键。
- 主设置窗口所有页面与侧边翻译正文都能在鼠标悬停时使用滚轮滚动。
- 侧边翻译窗口可以稳定拖动，长文本始终限制在当前显示器工作区内，底部操作栏始终可见。
- 在普通 Chrome/Edge 网页中，现有原位译文随根页面及常见嵌套滚动容器即时移动。
- 网页滚动本身不触发 OCR 或 DeepSeek 请求。
- 扩展缺失、断开或页面不受支持时，静态翻译继续可用且不会显示错误位置的旧译文。

## 非目标

- 不为游戏、聊天客户端、桌面 PDF 阅读器或其他任意应用实现通用视觉跟踪。
- 不自动重新翻译滚动后新进入视口的内容；用户可以再次框选。
- 不支持 `chrome://`、`edge://`、浏览器扩展商店和浏览器内置 PDF 阅读器等受保护页面。
- 不自动绕过浏览器的扩展安装安全限制；首次由用户手动加载解压扩展。
- 不发布到 Chrome Web Store 或 Microsoft Edge Add-ons。

## 总体架构

### 桌面端

桌面端保留现有 WPF/.NET 8 结构，并新增以下边界清晰的组件：

- `HotkeyGesture`：解析、格式化和验证快捷键组合。
- `HotkeyRegistrationCoordinator`：以“试注册新快捷键，失败则恢复旧快捷键”的事务方式更新注册。
- `MouseWheelRouter`：把未被控件消费的滚轮事件转发给鼠标下最近的可滚动 `ScrollViewer`。
- `SidePanelLayoutService`：依据当前显示器工作区计算侧边窗口初始位置、最大高度和安全边界。
- `BrowserBridgeServer`：桌面主进程中的命名管道服务，接收浏览器原生消息宿主转发的事件。
- `BrowserTrackingSession`：把一次翻译结果与浏览器窗口、标签页、页面导航和初始滚动位置绑定。
- `OverlayFollowCoordinator`：把网页 CSS 像素滚动量转换为当前显示器 DIP 位移，并移动、裁剪或隐藏覆盖窗口。

### 浏览器扩展

新增一套 Chrome/Edge 共用的 Manifest V3 扩展：

- 内容脚本监听根文档和常见嵌套滚动容器的 `scroll` 事件。
- 内容脚本使用 `requestAnimationFrame` 合并同一帧内的重复事件。
- 扩展 Service Worker 维护 `runtime.connectNative()` 长连接。
- 扩展发送活动标签、窗口边界、随机文档令牌、导航代次、滚动目标边界、滚动差值、`devicePixelRatio` 和视口尺寸。
- 扩展只收集定位所需的几何数据，不读取、记录或发送网页正文。
- 扩展清单携带固定公钥，使本地解压安装在 Chrome 和 Edge 中得到可预期的扩展 ID，供原生消息清单精确放行。

### 原生消息宿主

浏览器不能直接连接已运行的 WPF 对象，因此同一个桌面可执行程序支持原生消息宿主启动路径：

1. Chrome/Edge 根据当前用户注册的 Native Messaging 清单启动 `ScreenTranslator.App.exe`。
2. 程序检测浏览器传入的扩展来源参数后，不启动 WPF 主界面，而是进入标准输入/输出原生消息循环。
3. 宿主把长度前缀 JSON 消息转发给已运行桌面主进程的命名管道。
4. 桌面主进程返回会话状态；宿主再把响应写回浏览器。

正常启动应用和原生消息宿主使用不同执行路径，互不占用 UI 线程。

## 交互设计

### 快捷键录制

快捷键页把当前只会恢复默认值的按钮改为“修改快捷键”：

1. 点击后进入录制状态，按钮和提示显示“请按新的组合键”。
2. 录制期间暂时注销当前全局快捷键，防止用户按下原组合时意外启动框选。
3. `Esc` 取消录制；`Backspace` 恢复默认快捷键。
4. 组合键必须包含 `Ctrl`、`Alt`、`Shift` 或 `Windows` 中至少一个修饰键，并包含一个非修饰键。
5. 禁止单独使用系统保留键、纯修饰键和明显危险的系统组合。
6. 桌面端尝试注册新组合。
7. 注册成功后更新 `AppSettings.Hotkey` 并立即持久化。
8. 注册失败或取消录制时重新注册旧组合，页面显示结果，设置文件保持旧值。
9. 启用开关只控制注册状态，不覆盖用户保存的组合。

默认快捷键保留为迁移后备值，但首次成功修改后不再自动恢复默认。

### 鼠标滚轮

主窗口在页面内容根节点安装统一预览滚轮处理：

- 从鼠标命中元素向上查找最近的 `ScrollViewer`。
- 只有目标确实可以沿滚轮方向继续滚动时才处理事件。
- 使用系统滚轮增量换算滚动距离，并保留触控板产生的小增量。
- `ComboBox` 下拉列表、数值控件和正在直接处理滚轮的控件拥有优先权，避免滚轮同时修改值和滚动页面。
- 内层滚动区到达顶部或底部后，事件可继续交给外层滚动区。

同一行为同时应用于所有设置页和侧边翻译正文。

### 侧边翻译窗口

- 取消 `SizeToContent="Height"`，改为手动计算初始高度。
- 窗口高度限制为当前显示器工作区的 80%，同时保留合理的最小高度。
- 布局固定为“标题栏、进度条、可滚动正文、固定底栏”四行。
- 正文滚动区独占剩余空间，译文再长也不会改变底栏位置。
- 标题栏通过 Win32 非客户区拖动消息移动窗口，即使 `ShowActivated=false` 也能可靠拖动且不抢走浏览器输入焦点。
- 支持从窗口边缘调整大小，最小尺寸确保底部按钮不会重叠。
- 拖动和调整大小结束时，把窗口限制回当前显示器工作区，至少保留完整标题栏。
- 当前会话内记住用户手动位置；下一次旁显优先使用该位置，若显示器布局变化则重新夹取到有效工作区。

## 浏览器跟随数据流

### 建立会话

1. 用户触发框选时，桌面端在显示选择遮罩前记录前台窗口句柄、进程名、窗口边界和显示器缩放。
2. 如果进程为 `chrome.exe` 或 `msedge.exe` 且扩展已连接，桌面端请求对应浏览器窗口的活动标签信息。
3. OCR 和 DeepSeek 返回后，现有覆盖窗口仍以绝对屏幕坐标显示。
4. `BrowserTrackingSession` 保存初始覆盖坐标、框选裁剪区、标签 ID、窗口 ID、随机文档令牌、导航代次、初始滚动位置和显示器缩放。
5. 如果无法可靠关联浏览器窗口和活动标签，则不建立跟随会话，仍显示静态结果。

### 根页面滚动

扩展发送新的根页面滚动位置。桌面端按下式计算覆盖层 DIP 位移：

`deltaDip = deltaCss * devicePixelRatio / monitorScale`

覆盖窗口仅做本地坐标更新，不重新截图、不运行 OCR、不访问 DeepSeek。覆盖块完全离开原框选裁剪区后隐藏，重新进入时恢复。

### 嵌套滚动容器

扩展为滚动目标附带当前视口矩形和滚动差值。桌面端只移动中心点位于该矩形内的覆盖块。若容器几何信息无法映射到屏幕、跨域 frame 无法关联，或同一帧出现互相矛盾的多个滚动目标，则隐藏受影响覆盖块并终止该会话，避免保留错位文字。

### 平滑滚动与节流

- 内容脚本每个动画帧最多发送一次合并后的滚动更新。
- 桌面端在 UI Dispatcher 上合并积压事件，只应用最新位置。
- 移动覆盖层不播放位置动画，避免与浏览器平滑滚动叠加产生滞后。
- DeepSeek 翻译任务与浏览器滚动通道完全分离。

### 会话失效

出现以下任一情况时立即隐藏并结束旧跟随会话：

- 标签页切换、关闭或丢失。
- 页面导航、刷新或随机文档令牌变化。
- 浏览器缩放、显示器 DPI 或网页视口尺寸发生不可连续校正的变化。
- 浏览器窗口最小化、关闭或移动到其他 DPI 显示器。
- 原生消息连接断开超过短暂重连窗口。
- 接收到乱序导航代次或非法数值。

页面仍在原标签中且只是普通滚动时，跟随会话持续有效。

## 扩展安装与连接状态

发布目录包含 `browser-extension` 文件夹。用户分别在 Chrome 和 Edge 的扩展管理页开启开发者模式并选择“加载已解压的扩展程序”。

桌面设置页新增“浏览器跟随”状态卡：

- Chrome：已连接、未安装或未连接。
- Edge：已连接、未安装或未连接。
- “打开 Chrome 扩展页”按钮。
- “打开 Edge 扩展页”按钮。
- “打开扩展文件夹”按钮。
- 简短安装步骤和受支持页面说明。

应用在当前用户范围写入 Chrome 与 Edge 的 Native Messaging 注册表项，不请求管理员权限。注册失败只禁用浏览器跟随，不影响主应用启动。

## 安全与隐私

- 扩展不读取或发送网页正文、表单值、Cookie、存储内容或网络请求。
- 扩展消息只包含标签/窗口身份、随机文档令牌和几何数据，不把网页 URL 传给桌面端。
- 原生消息清单只允许固定扩展 ID，不使用通配来源。
- 命名管道使用包含当前用户 SID 的名称，并通过 ACL 只允许当前 Windows 用户访问。
- 浏览器消息不包含 DeepSeek API Key；API Key 继续只由现有 DPAPI 存储。
- 所有坐标、缩放和消息长度在进入 UI 层前进行范围验证。

## 错误处理与降级

- 新快捷键注册冲突：恢复旧快捷键并显示冲突提示。
- 旧快捷键恢复也失败：禁用快捷键，保留设置值，并提示从托盘启动翻译。
- 滚轮没有可滚动目标：不标记事件为已处理。
- 侧边窗口计算到无效工作区：回退到主显示器中央的安全尺寸。
- 扩展未安装或未连接：静态翻译正常工作，状态栏显示“网页跟随未连接”。
- 原生消息宿主异常退出：扩展指数退避重连；桌面端隐藏已绑定覆盖层。
- 页面事件无法可靠解释：宁可隐藏旧译文，也不继续显示错位内容。

## 设置迁移

`AppSettings.CurrentVersion` 升级并增加：

- 已保存快捷键规范字符串。
- 快捷键启用状态。
- 浏览器跟随启用状态，默认开启。
- 侧边窗口最后位置和尺寸，可为空。

加载旧版本设置时沿用现有默认快捷键，其他新字段使用默认值。无法解析的快捷键回退到默认组合，并在设置页显示一次迁移提示。

## 测试策略

### 单元测试

- 快捷键解析、规范化、非法组合和显示格式。
- 新注册成功、冲突回滚、双重失败禁用。
- CSS 像素到 WPF DIP 位移换算，包括 100%、125%、150%、200% DPI 与浏览器缩放。
- 根滚动、嵌套容器过滤、覆盖裁剪和会话失效。
- 乱序、NaN、无限值、过大位移和错误导航代次拒绝。
- 侧边窗口尺寸与工作区夹取。

### WPF 集成测试

- 鼠标位于设置页空白、卡片、文本和侧边正文时滚轮生效。
- 内外层滚动区在边界处正确交接。
- 下拉框打开时滚轮不同时滚动页面。
- 长译文出现正文滚动条，底部按钮保持可见。
- 非激活侧边窗口可以拖动且浏览器焦点行为符合预期。

### 扩展测试

- Manifest V3 文件通过结构检查。
- 根页面鼠标滚轮、触控板、键盘、拖动滚动条和脚本滚动均产生合并后的差值事件。
- 常见 `overflow: auto` 容器发送目标矩形和差值。
- 标签切换、导航、刷新、缩放和断线产生正确失效事件。
- Chrome 与 Edge 使用同一扩展源码运行。

### 手工验收

- Chrome/Edge 普通长网页在 100% 和 125% 浏览器缩放下滚动，译文与原文保持同步。
- Windows 100%、125%、150% 显示缩放以及双显示器环境下坐标正确。
- 快速平滑滚动无明显逐帧滞后，滚动期间没有新的 DeepSeek 请求。
- 切换标签、刷新、缩放和关闭浏览器后旧译文立即消失。
- 未安装扩展时全部原有静态翻译流程正常。
- 快捷键冲突不会丢失上一个可用组合。
- 主窗口与旁显窗口均能使用鼠标滚轮。

## 完成定义

- 三个交互缺陷均有自动测试或可重复的集成验证。
- Chrome/Edge 普通网页滚动只触发本地覆盖层移动，不触发 OCR 或 DeepSeek。
- 受支持页面中滚动后的覆盖坐标误差不超过 2 DIP。
- 无法可靠跟随时不会留下持续错位的译文。
- 扩展、原生消息宿主和桌面端均能从发布目录完成安装与连接。
- `dotnet test ScreenTranslator.sln -c Release` 全部通过。
- 自包含 win-x64 发布目录包含桌面应用、浏览器扩展和安装说明。
