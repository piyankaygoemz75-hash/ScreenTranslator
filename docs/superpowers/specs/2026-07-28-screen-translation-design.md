# 屏幕翻译软件设计说明

## 1. 产品目标

构建一款面向 Windows 10/11 的桌面屏幕翻译软件。用户按下全局快捷键后，可以框选任意屏幕区域，软件在本地完成 OCR，再调用用户配置的 AI API 翻译文字，并以“原位覆盖”或“原文旁边”两种方式显示译文。

第一版专注单次框选翻译，不包含持续扫描、实时游戏字幕、用户账户、云同步和付费系统。产品应当在普通软件、浏览器、文档、图片及无边框窗口游戏中可靠工作；受保护内容和独占全屏游戏不保证可捕获。

## 2. 平台与技术路线

### 2.1 目标平台

- Windows 10 22H2 及以上版本。
- Windows 11 当前受支持版本。
- x64 为第一版发布架构。
- 支持单屏、多屏以及 100%、125%、150%、175%、200% 缩放组合。

### 2.2 技术栈

- .NET 8。
- WPF 负责设置窗口、托盘菜单、框选层和译文覆盖层。
- WPF UI 4.x 提供 FluentWindow、NavigationView、Fluent 控件、主题和 Windows 11 系统背景集成。
- CommunityToolkit.Mvvm 负责视图模型和命令。
- Microsoft.Extensions.DependencyInjection 负责模块装配。
- Windows.Graphics.Capture 负责首选屏幕捕获，GDI BitBlt 作为兼容后备。
- Windows.Media.Ocr 负责第一版本地 OCR。
- HttpClient 负责 AI API 请求。
- System.Text.Json 负责配置和结构化翻译响应。
- Windows DPAPI 负责 API Key 加密。
- MSIX 负责安装和赋予 Windows OCR 所需的包身份。

选择 WPF 而非 Electron 或 Tauri，是因为第一版的关键风险集中在透明置顶窗口、鼠标穿透、全局快捷键、多显示器和 DPI 坐标，而不是跨平台 UI。使用 WPF UI 让设置窗口和结果面板接近 Windows 11 原生 Fluent 体验，同时保留 WPF 对覆盖窗口的成熟控制。OCR 和翻译都通过接口隔离，未来可以替换引擎或增加跨平台客户端。

### 2.3 Windows 11 视觉规范

软件以 Windows 11 的 Fluent Design 为唯一视觉方向，不设计独立品牌皮肤：

- 主设置窗口使用 `FluentWindow`、系统标题栏行为和左侧 `NavigationView`。
- 主窗口背景优先使用 Mica；Windows 10、关闭透明效果、远程桌面、高对比度或硬件不支持时自动回退到纯色背景。
- 旁显面板和短暂弹出层使用 Acrylic 风格；原位覆盖块使用高对比度半透明纯色，避免复杂背景导致文字不可读。
- 字体优先使用 Segoe UI Variable；中文由系统语言字体映射回退，不捆绑替代字体。
- 正文使用 14 有效像素 Regular，辅助文本不小于 12 有效像素，标题使用 Semibold。
- 图标使用 Segoe Fluent Icons 或 WPF UI 自带 Fluent System Icons，不混用 Emoji 和其他图标风格。
- 窗口和卡片采用 Windows 11 圆角、细描边与轻量阴影；控件不使用夸张渐变、霓虹描边或大面积高饱和色。
- 强调色跟随 Windows 系统强调色，危险操作使用系统危险色。
- 默认跟随系统浅色或深色主题，用户可以强制浅色或深色。
- 尊重系统高对比度、透明效果和减少动画设置；不可用的材质必须有等价纯色后备。
- 动画只用于面板出现、进度状态和模式切换，时长短且不阻塞输入。

设置窗口的导航顺序固定为“常规、翻译、外观、快捷键、隐私、关于”，设置入口位于导航底部。常规设置采用 Windows 11 设置应用式分组卡片，每张卡片只承载一个概念。

## 3. 用户体验

### 3.1 首次启动

首次启动进入简短设置页：

1. 选择目标语言，默认简体中文。
2. 填写 DeepSeek API Key。
3. 选择模型，默认 `deepseek-v4-flash`，可切换 `deepseek-v4-pro`。
4. 点击“测试连接”，成功后保存。
5. 显示默认快捷键 `Alt + Shift + T`，允许修改。
6. 选择默认显示方式，默认“原文旁边”。

设置完成后软件缩入系统托盘。不开启“开机启动”时，软件不会修改系统启动项。

### 3.2 框选翻译

1. 用户按下全局快捷键。
2. 软件取消尚未完成的旧请求，并暂时隐藏自身的译文窗口。
3. 捕获所有显示器当前画面。
4. 每个显示器显示一层冻结画面和半透明暗色遮罩。
5. 用户按住鼠标左键拖拽选择区域。
6. 拖拽过程中显示区域尺寸；松开鼠标后确认选择。
7. 选区小于 8×8 物理像素时视为误操作并取消。
8. 软件裁剪选区、执行 OCR、调用翻译接口。
9. 处理期间在选区附近显示非抢焦点的进度提示。
10. 翻译完成后按用户设置显示结果。

`Esc` 在框选、OCR 或翻译阶段都能取消当前操作。再次按全局快捷键也会取消旧操作并开始新框选。

### 3.3 原位覆盖

- OCR 输出按段落形成文本块，每块保留屏幕物理坐标。
- 每个文本块对应一个置顶、无边框、默认鼠标穿透的译文层。
- 译文层使用附近背景色取样加不透明度，确保遮住原文并保持可读。
- 译文字号从原文字框高度推算，在设定范围内自适应。
- 译文放不下时依次采用减小字号、增加块高度、显示省略提示的策略。
- 用户将鼠标移到选区右上角的控制柄后，可以复制、固定、切换旁显、重新翻译或关闭。
- 按住 `Alt` 时所有覆盖块暂时隐藏，以便对照原文。

第一版的“覆盖”是清晰可读的译文卡片覆盖，不使用图像修复或背景重绘来伪造原始画面。

### 3.4 原文旁边

- 翻译面板优先显示在选区右侧。
- 右侧空间不足时依次尝试左侧、下方和上方。
- 面板不会超出当前显示器工作区。
- 面板显示完整译文，并提供“查看原文、复制、固定、切换覆盖、重译、关闭”。
- 未固定面板在下一次翻译成功时自动关闭；固定面板保留。

### 3.5 托盘与设置

托盘菜单包含：

- 开始框选翻译。
- 显示或隐藏全部译文。
- 打开设置。
- 暂停或恢复全局快捷键。
- 退出。

设置页包含：

- 源语言自动检测或指定语言。
- 目标语言。
- 翻译风格：自然、直译、学习模式。
- 自定义上下文和术语。
- DeepSeek 模型、API Key、连接测试和高级 Base URL 覆盖。
- 默认显示方式、字体、字号范围、背景透明度。
- 全局快捷键。
- 是否保存纯文本翻译历史，默认关闭。
- 是否开机启动，默认关闭。

## 4. 系统架构

### 4.1 模块边界

#### AppHost

负责程序生命周期、依赖注入、单实例、托盘入口和全局异常处理，不包含 OCR 或翻译逻辑。

#### HotkeyService

注册、注销和检测全局快捷键冲突。它只发布“开始捕获”命令，不直接创建窗口。

#### CaptureCoordinator

编排一次翻译会话：取消旧会话、隐藏旧窗口、捕获显示器、启动框选、裁剪位图并把结果交给 OCR。

#### ScreenCaptureService

以物理像素输出显示器截图、显示器边界、缩放比例和设备标识。首选 Windows.Graphics.Capture，失败时回退到 GDI。它不负责框选 UI。

#### SelectionOverlay

每个显示器一个 WPF 窗口，显示冻结截图、暗色遮罩和选择矩形。它返回统一虚拟桌面坐标中的物理矩形。

#### IOcrEngine

输入裁剪后的位图和语言偏好，输出文字块：

```text
OcrBlock
  Id
  Text
  Confidence
  BoundsInCapturePixels
  ReadingOrder
```

第一版实现 `WindowsOcrEngine`。后续 RapidOCR、PaddleOCR 或 AI 视觉 OCR 通过同一接口增加。

#### TextLayoutService

清理 OCR 空白、按空间关系合并行和段落、确定阅读顺序，并把选区内坐标转换成虚拟桌面坐标。该模块不调用 AI。

#### ITranslationProvider

输入带稳定 ID 的文本块、语言和翻译风格，输出相同 ID 的译文。第一版只实现 `DeepSeekTranslationProvider`。接口边界保留，以便未来增加其他服务，但不在第一版暴露其他供应商选项。

#### TranslationOrchestrator

构造结构化提示词、调用翻译服务、验证返回 ID、执行一次格式修复重试，并把译文与 OCR 坐标重新关联。

#### OverlayManager

创建、更新和销毁原位覆盖层或旁显面板，管理固定状态、鼠标穿透、屏幕边缘避让和 `Alt` 临时隐藏。

#### SettingsService

负责读取和保存非敏感配置。API Key 交给 `SecretStore`，配置文件只保存密钥引用。

#### SecretStore

使用当前 Windows 用户范围的 DPAPI 加密和解密 API Key。密钥不写入日志或异常信息。

### 4.2 数据流

```text
Hotkey
  -> CaptureCoordinator
  -> ScreenCaptureService
  -> SelectionOverlay
  -> selected bitmap + physical screen rectangle
  -> IOcrEngine
  -> TextLayoutService
  -> TranslationOrchestrator
  -> ITranslationProvider
  -> translated blocks
  -> OverlayManager
```

每次操作都有独立的 `TranslationSessionId` 和 `CancellationToken`。任何旧会话返回的迟到结果都必须因为会话 ID 不匹配而被丢弃。

## 5. DeepSeek 接口设计

### 5.1 连接配置

第一版直接调用 DeepSeek 官方 OpenAI 兼容 Chat Completions 接口：

- 默认 Base URL：`https://api.deepseek.com`。
- 请求路径：`/chat/completions`。
- 默认模型：`deepseek-v4-flash`。
- 可选模型：`deepseek-v4-pro`。
- 默认关闭思考模式，发送 `"thinking": {"type": "disabled"}`，降低短文本翻译延迟和输出成本。
- 使用 `Authorization: Bearer <API_KEY>`。
- 请求超时默认 15 秒。
- 使用非流式请求，确保完整 JSON 验证通过后再按文本块显示。

不使用已经进入淘汰阶段的 `deepseek-chat` 和 `deepseek-reasoner` 模型别名。设置页允许高级用户覆盖 Base URL，以便应对官方域名变化或企业代理，但不承诺兼容其他服务商。

连接测试发送最小翻译请求，验证密钥、模型和 JSON 输出能力。成功后显示当前模型与请求耗时；失败时只显示脱敏后的状态码和错误信息。

### 5.2 翻译约束

发送给 AI 的默认内容只有 OCR 文本，不包含截图。请求包含：

```json
{
  "sourceLanguage": "auto",
  "targetLanguage": "zh-CN",
  "style": "natural",
  "context": "",
  "blocks": [
    {
      "id": "block-1",
      "text": "Source text"
    }
  ]
}
```

请求设置 `response_format: {"type": "json_object"}`，系统提示词明确包含“JSON”及完整输出示例。DeepSeek 必须返回：

```json
{
  "blocks": [
    {
      "id": "block-1",
      "translation": "译文"
    }
  ]
}
```

返回空内容、缺少 ID、包含重复 ID、因为输出长度截断或不是有效 JSON 时，编排器用原始响应执行一次格式修复请求。第二次仍失败时，本次翻译失败并显示可读错误，不把无法定位的译文放到错误位置。

## 6. 坐标与窗口规则

- 捕获、OCR、布局和会话数据统一使用物理像素。
- WPF 窗口边界只在最终显示时转换成设备无关像素。
- 每个显示器单独保存变换矩阵，不使用主显示器 DPI 代替其他显示器。
- 跨显示器拖拽不在第一版支持；选择从哪个显示器开始，就限制在哪个显示器完成。
- 覆盖窗口使用置顶、无任务栏图标和不激活样式。
- 正常状态启用鼠标穿透；控制柄展开时临时接受鼠标输入。
- 捕获前隐藏所有自身窗口；捕获结束后只恢复固定窗口。

## 7. 错误处理

### 7.1 捕获错误

- 不支持屏幕捕获时自动尝试 GDI。
- 两种方式都失败时显示“无法捕获当前画面”。
- 捕获结果近乎全黑时提示受保护内容或独占全屏限制。

### 7.2 OCR 错误

- 没有识别到文字时显示轻量提示，并提供复制截图和重试入口。
- 缺少 OCR 语言包时显示缺失语言及系统设置入口。
- OCR 引擎异常不会导致托盘进程退出。

### 7.3 API 错误

- 401/403：提示检查 API Key 或服务权限。
- 404：提示检查 Base URL 和模型名。
- 429：提示限流或余额不足。
- 超时：提示网络或服务响应过慢，可立即重试。
- 5xx：提示服务暂时不可用。
- 用户取消不显示错误通知。

### 7.4 全局稳定性

- 未观察的后台异常写入脱敏日志。
- 连续失败不会自动无限重试。
- 新会话开始后，旧会话无权改变当前 UI。
- 设置文件损坏时备份原文件并恢复默认配置，密钥文件不随之删除。

## 8. 隐私与安全

- 默认只上传 OCR 文本。
- 第一版不提供截图上传或 AI 视觉 OCR，避免界面与隐私承诺不一致。
- 原始截图仅保存在进程内存中，会话结束后释放。
- 翻译历史默认关闭；开启时只保存源文本、译文、语言和时间，不保存截图。
- API Key 使用当前用户范围 DPAPI 加密。
- 日志不得包含 API Key、Authorization 头、完整请求正文或截图。
- 设置页明确标识远程 API 会收到识别后的文字。

## 9. 性能目标

在常见办公设备上：

- 按下快捷键后 150 毫秒内显示冻结框选层。
- 取消操作后 100 毫秒内关闭框选层。
- 选区小于 1920×1080 时，本地 OCR 目标耗时低于 1 秒。
- 网络翻译耗时不设绝对保证，但 UI 必须持续响应并可取消。
- 空闲托盘状态不持续捕获屏幕，不执行轮询 OCR。
- 同一时间最多存在一个非固定翻译会话。

这些是工程目标，不作为第三方 API 延迟承诺。

## 10. 测试策略

### 10.1 单元测试

- OCR 行合并和阅读顺序。
- 物理像素与 WPF 坐标转换。
- 不同显示器 DPI 的映射。
- 旁显面板的屏幕边缘避让。
- 结构化提示词生成和 AI 响应验证。
- 缺失、重复、乱序 block ID。
- 设置迁移和损坏配置恢复。
- DPAPI 存取接口通过可替换实现测试，不在测试中依赖真实用户密钥。

### 10.2 集成测试

- 使用本地模拟 HTTP 服务测试成功、401、404、429、500、超时和无效 JSON。
- 使用固定中英日韩截图测试 OCR 结果结构。
- 验证取消令牌和迟到响应不会更新新会话。
- 验证捕获时自身覆盖窗口不可见。

### 10.3 手工验收矩阵

- Windows 10 与 Windows 11。
- 单显示器和双显示器。
- 100%、125%、150%、200% 缩放。
- 主屏在左、右及带负坐标的布局。
- 浏览器、PDF、图片、视频、无边框窗口游戏。
- DeepSeek `deepseek-v4-flash` 和 `deepseek-v4-pro`。
- 原位覆盖、旁显、固定、复制、重译、取消。
- 快捷键冲突、断网、密钥错误、接口超时。

## 11. 发布与验收

第一版通过 MSIX 发布 x64 安装包。安装程序不默认启用开机启动，不安装浏览器扩展，不添加常驻服务。卸载时删除程序文件；用户配置和历史是否保留由卸载提示明确选择。

第一版完成必须同时满足：

1. 配置有效 API 后，用户可以从托盘或快捷键开始框选。
2. 单屏和双屏混合 DPI 下，选区与译文位置没有明显偏移。
3. 中、英、日、韩常规印刷体能够进入 OCR 和翻译流程。
4. 两种显示模式可随时切换。
5. 当前操作可以在任意阶段取消。
6. API Key 不以明文保存在磁盘或日志。
7. API 错误有明确提示且不会导致程序退出。
8. 默认不上传截图、不保存截图、不保存翻译历史。
9. 设置窗口、旁显面板和控件在 Windows 11 下呈现统一 Fluent 风格，并正确跟随浅色、深色和系统强调色。

## 12. 后续版本边界

第一版稳定后，再分别设计以下独立功能：

- 固定区域持续扫描和游戏字幕模式。
- RapidOCR、PaddleOCR 和 AI 视觉 OCR。
- 上下文窗口、术语库、缓存与费用统计。
- 原文背景修复和更自然的图像内嵌翻译。
- ARM64、macOS 和 Linux 客户端。

这些功能不进入第一版实施计划，避免削弱快捷框选翻译的完成度。
