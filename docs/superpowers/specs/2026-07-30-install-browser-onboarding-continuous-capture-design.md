# 安装、浏览器引导与连续框选设计

## 目标

为屏译 `v0.2.0` 提供可公开分发的一键安装包、可理解且可恢复的
Chrome/Edge 扩展连接流程，以及不会阻塞下一次选择的连续框选工作流。
完成后自动构建安装包、便携包和浏览器扩展包，并发布到 GitHub Release。

## 范围与约束

- 支持 Windows 10 2004 及以上的 x64 系统。
- 安装器默认按当前用户安装，不请求管理员权限。
- 桌面程序、Native Messaging Host 注册和连接检测自动完成。
- Chrome/Edge 普通用户环境不采用企业策略强装扩展。
- 本地扩展首次加载仍由用户在浏览器扩展页确认；流程由程序引导并实时反馈。
- 现有一次性框选快捷键行为保持不变。
- 连续模式由主界面和托盘显式启动，`Esc` 或右键结束采集。
- 连续模式停止采集后，已排队的工作继续完成，已有译文保留。
- 不在本次范围内实现应用内自动更新、浏览器商店提交或代码签名。

## 方案选择

采用 Inno Setup 当前用户安装器、引导式扩展加载和有界后台处理队列。

不采用 MSIX，因为当前缺少可信代码签名证书，并且打包后的 Native Messaging
路径与升级处理会显著增加首版复杂度。不采用企业策略强制安装扩展，因为这会
让普通用户浏览器显示“由组织管理”，也不符合公开软件应由用户主动授权扩展的
安全边界。

## 安装与发布

安装目录为：

```text
%LOCALAPPDATA%\Programs\ScreenTranslator
```

安装包包含自包含桌面程序、固定目录下的浏览器扩展、许可证和必要说明。安装器
创建开始菜单、可选桌面快捷方式和卸载入口，可选设置开机启动。安装完成后启动
程序，由程序按实际安装路径注册 Native Messaging Host。

覆盖安装先请求已运行实例正常退出，保留 `%LOCALAPPDATA%\ScreenTranslator`
下的设置和 DPAPI 密钥。卸载默认保留个人配置，并提供显式选项删除个人配置；
Native Messaging 注册和安装目录必须清理。

仓库新增可复现的发布脚本和 GitHub Actions 工作流，输出：

- `ScreenTranslator-Setup-x64.exe`
- `ScreenTranslator-Portable-x64.zip`
- `ScreenTranslator-Browser-Extension.zip`
- `SHA256SUMS.txt`

版本定为 `0.2.0`，Git 标签和 Release 名称为 `v0.2.0`。

## 浏览器扩展安装与连接

桌面程序继续使用固定扩展 ID 和 Native Messaging 协议。启动时注册当前程序
路径，检测 Chrome/Edge 是否安装，并分别展示以下状态：

- 未检测到浏览器
- 浏览器已安装，扩展未连接
- 正在等待扩展连接
- 已连接
- 注册失败，可修复

设置页提供“安装到 Chrome”“安装到 Edge”“修复连接”和“打开扩展目录”。
本地扩展流程会打开对应扩展管理页、打开稳定扩展目录并把目录路径复制到剪贴板，
随后轮询现有桥接连接。扩展连接成功时界面即时更新，不要求重启任一端。

扩展断开后采用现有限速重连机制。连接失败不影响静态原位翻译，只将网页跟随
降级为静态显示。未来扩展上架商店后，安装按钮可替换为商店 URL，而桌面协议和
状态模型保持不变。

## 连续框选架构

新增连续捕获协调器，明确分离“采集循环”和“处理队列”：

1. 采集循环获取最新屏幕快照并等待用户框选。
2. 完成框选后生成不可变工作项，包含裁剪图、显示器、绝对边界、来源窗口和
   浏览器上下文。
3. 工作项写入容量为 5 的有界队列。
4. 采集循环立即进入下一轮；队列满时显示等待状态，腾出位置后恢复。
5. 单个后台消费者按顺序执行 OCR 和 DeepSeek 翻译，避免并发请求失控。
6. `Esc` 或右键只停止采集并完成队列写入，消费者继续处理现有项目。
7. 应用退出时取消采集和消费者，并等待资源有界释放。

开始连续模式前检查 API Key。缺少 Key 时不创建会话，直接引导用户进入翻译
设置。单个项目 OCR 无文本、网络失败或响应校验失败只形成该项目的非阻塞错误
结果，不终止连续会话，并提供重试。

## 结果保留与窗口归属

一次性模式维持现有“新翻译替换旧结果”的语义。连续模式不调用全局关闭结果：

- 原位模式为每次选择创建一个结果组，支持清除此组和清除全部。
- 旁显模式复用一个连续结果面板，以可滚动卡片按完成顺序追加项目。
- 每个结果组保存来源顶层窗口句柄；前台窗口变化时，各组独立隐藏或恢复。
- 删除最后一个组时释放对应的前台窗口监视和浏览器跟随会话。

浏览器跟随从单例协调器调整为按浏览器、窗口、标签页和文档标识分组的会话注册表。
同一页面的多个结果组共享滚动消息，但各自保留选择边界。标签切换、导航、缩放
或窗口状态变化只使对应页面组失效，不影响其他窗口和桌面应用结果。

## 用户界面

主界面保留“开始框选”，新增“连续框选”。托盘菜单增加同名入口。连续框选遮罩
显示轻量提示：

```text
连续框选 · Esc 结束 · 待处理 N
```

主窗口和托盘状态区显示“正在连续框选”“正在处理 N 项”“队列已完成”。错误采用
状态文本或结果卡片，不使用阻塞式消息框打断连续操作。

浏览器设置卡片保持 Windows 11 风格，并为每个浏览器提供独立状态与操作按钮。

## 测试与验收

自动测试覆盖：

- 连续会话启动、停止、容量 5、顺序处理和单项失败隔离。
- `Esc` 停止采集但排队任务继续完成。
- 一次性模式仍替换旧结果，连续模式保留并分组结果。
- 多来源窗口独立隐藏、恢复和清理。
- 同一网页多组滚动、不同标签隔离和页面导航失效。
- 浏览器检测、Native Messaging 注册、修复和状态转换。
- 安装器文件清单、静默安装、覆盖安装和静默卸载。

发布前必须通过 Release 构建、全部 .NET 测试、全部浏览器扩展测试、双显示器混合
DPI 手工验证，以及 Chrome/Edge 的首次连接、重启重连和断线恢复验证。

GitHub Release 必须包含四类产物、校验文件、中文安装说明和已知限制。未签名安装包
需明确标注可能出现 Windows SmartScreen“未知发布者”提示。
